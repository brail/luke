# Decisions in force — Secrets and sensitive data

> Current guidance, kept up to date; not a decision record. The ADRs linked here decide: where this page and an Accepted ADR disagree, the ADR holds.

_Last reviewed: 2026-11-22_

## Rules in force

- `getMasterKey` (`packages/core/src/crypto/secrets.server.ts`) reads the 32-byte `~/.luke/secret.key` and, when it is absent, creates it with mode 0600 (and `~/.luke` with mode 0700), modes applied at creation only, the 32-byte length being the sole validation of an existing key. [ADR-020](../020-master-key-scope-and-rotation-limits.md)
- `deriveSecret` applies HKDF-SHA256 with the salt `luke`, a 32-byte output and base64url encoding, the info domains in use being `api.jwt`, `nextauth.secret`, `cookie.secret` and `luke:download-token` (`apps/api/src/utils/downloadToken.ts`), and nothing constrains the set: a new domain is a new string passed to it. [ADR-020](../020-master-key-scope-and-rotation-limits.md#errata)
- API tokens are signed HS256 with `iss: 'urn:luke'`, `aud: 'luke.api'` and a 5-second clock tolerance, and live 8 hours (`JWT_EXPIRES_IN_SECONDS`), never past 12 hours from the login their session descends from (`SESSION_ABSOLUTE_LIFETIME_SECONDS`). [ADR-020](../020-master-key-scope-and-rotation-limits.md#errata)
- `encryptValue` and `decryptValue` (`apps/api/src/lib/configManager.ts`) use the raw master key for AES-256-GCM with no derivation step, so every `AppConfig` row flagged `isEncrypted` is readable only under the exact key that wrote it. [ADR-020](../020-master-key-scope-and-rotation-limits.md)
- Every writer stores a key listed in `SECRET_CONFIG_KEYS` encrypted and one listed in `PLAINTEXT_CONFIG_KEYS` in plaintext, whatever the caller asks (both lists maintained in `packages/core/src/schemas/config.ts`); every other registered key is encrypted at the caller's choice, so the set of encrypted rows stays open. [ADR-020](../020-master-key-scope-and-rotation-limits.md#errata), [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata), [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md#errata)
- `wrapDek` and `unwrapDek` (`apps/api/src/lib/backup/crypto.ts`) are `encryptValue` and `decryptValue`, so each backup's data-encryption key is wrapped under the master key in `BackupRecord.wrappedDekHex` and the `<backupId>.meta.json` sidecar, and only `wrapDekWithPassphrase` and `unwrapDekWithPassphrase` (Argon2id, for `.lukebak` exports) are independent of it. [ADR-020](../020-master-key-scope-and-rotation-limits.md)
- Deleting or replacing the master key on an instance that holds data is not a supported way to revoke sessions: it leaves every encrypted `AppConfig` row and every wrapped backup key unreadable while the original key is unavailable, and permanently if no copy of it survives. [ADR-020](../020-master-key-scope-and-rotation-limits.md)
- No re-entry or re-encryption routine exists — neither the seed nor `config.exportJson` restores an encrypted row — and an administrator recovers only by entering a value again where a settings page marks it as not decrypting, which the LDAP and storage pages do. [ADR-020](../020-master-key-scope-and-rotation-limits.md#errata)
- A `.lukebak` export taken beforehand survives a key change, but creating one requires the key that wrapped the backup's key (`maintenance.backup.prepareExport` calls `unwrapDek`), so it is a precaution that must precede the change, never a recovery afterwards. [ADR-020](../020-master-key-scope-and-rotation-limits.md)
- A replaced key has no dedicated detection: `getMasterKey` creates a missing key and `validateMasterKey` checks only its length, `validateCriticalConfig` aborts production startup only when a `CRITICAL_CONFIG_KEYS` key is itself stored encrypted, the `secrets` probe cannot tell one key from another, and the `ldap` probe surfaces it only where `auth.ldap.enabled` is `true`. [ADR-020](../020-master-key-scope-and-rotation-limits.md#errata)
- After a key change, production web sessions end at their next refresh rather than at once: the Auth.js cookie stays decryptable because production takes `NEXTAUTH_SECRET` from the environment, while the API token inside it fails `auth.refreshToken`. [ADR-020](../020-master-key-scope-and-rotation-limits.md)
- A re-encryption routine for `AppConfig` and a rewrap of stored data keys are a separate, security-reviewed project that no record authorizes or designs, so the `luke_api_data` volume holding the key is never deleted, as a data-retention rule. [ADR-020](../020-master-key-scope-and-rotation-limits.md)
- Backup archives carry the encrypted rows and never the master key, a passphrase-wrapped `.lukebak` restoring the archive without the key but not making its encrypted values readable, and whether a copy of the key is held elsewhere, under what custody, is not decided. [ADR-020](../020-master-key-scope-and-rotation-limits.md)
- No value of the guarded set — `LocalCredential.passwordHash`, `UserToken.tokenHash`, and `BackupRecord.wrappedDekHex` with its `ivHex` and `authTagHex` — crosses the outbound boundary (a tRPC result, an HTTP response body, a log line, an `AuditLog.metadata` record), and reading one is confined to the code that consumes it for verification, a crypto operation or a write. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md)
- The outbound rule governs only what leaves the process: in-process values and protected storage may hold guarded fields by design (the `<backupId>.meta.json` sidecar, the audit-log archive in the private `backups` bucket), and personal data such as `Identity.metadata` is outside the guarded set. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md)
- An explicit `select` is the preferred form, particularly where a nested `include` would pull a guarded field into memory, but not a requirement, since `count`, `aggregate` and the `*Many` writes take no projection: the defect is a guarded value crossing the boundary. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md)
- `auditLog.list` (`audit:read_all`) returns `AuditLog.metadata` verbatim, filtered on write by `sanitizeMetadata`, which consults `FREE_TEXT_KEYS`, `MAP_VALUED_KEYS` and `SAFE_KEY_LIST` before the secret-name pattern, redacts an unlisted scalar and walks an unlisted object or array, the allowlist being bound to a type and refused at run time outside production. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md)
- Reading a decrypted configuration value requires `config:update`, stronger than the `config:read` that reads stored and masked values: `config.viewValue` masks an encrypted value as `[ENCRYPTED]` and its raw mode requires `config:update` and writes an audit row. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md)
- `config.getMultiple` (`config:read`) returns for each requested key, in the order asked, `found`, `isEncrypted` and the stored value or `null` for an encrypted key, with no decrypting mode, and `config.list` (`config:read`) returns `valuePreview`, `null` for an encrypted key and the stored value in full otherwise. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md#errata)
- `config.exportJson` (`config:update`) never decrypts: an encrypted key exports as `[ENCRYPTED]`, the rest in full when `includeValues` is set and as `null` otherwise. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md)
- Integration settings return no stored secret: `storage.getConfig` (`config:read` and the `settings.storage` section) answers `hasSecretKey` and `secretKeyUnreadable` and returns the S3 access key decrypted by choice, LDAP responds through schemas without its password, and `integrations.google.getConfig`, `integrations.nav.getPasswordState` and `integrations.mail.getPasswordState` decrypt through `getConfigForForm` only to answer `has*` and `*Unreadable` flags. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md#errata)
- `User.tokenVersion` is returned by `auth.login` and `auth.refreshToken` by design, for session revocation, and is not in the guarded set. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md)
- A credential row an earlier release stored in plaintext is read back as stored until `db:encrypt-secret-config` encrypts it. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md#errata)
- Enforcement of the outbound rule is human review plus the write-time audit filter, since no procedure validates its result with a tRPC `.output()` schema, and a reviewer asks whether a guarded value can reach a response, a log or an audit record from the code under review. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md)
