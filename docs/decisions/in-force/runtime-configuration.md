# Decisions in force — Runtime configuration

> Current guidance, kept up to date; not a decision record. The ADRs linked here decide: where this page and an Accepted ADR disagree, the ADR holds.

_Last reviewed: 2026-11-22_

## Rules in force

- A variable belongs in the environment only when a process needs it before it reaches the database, or a framework or the build reads it; credentials, tokens, application passwords and every other application setting live in AppConfig, and variables read only by test runners, CI and one-off scripts are outside this rule. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md)
- The [`CLAUDE.md` "Env Policy"](../../../CLAUDE.md#env-policy--firm-architectural-rule) section is the only maintained list of the variables permitted to apps/api and apps/web; no record or page keeps a copy. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md)
- `assertEnvPolicy` (`apps/api/src/lib/envPolicy.ts`) is the first step of `start()` in `apps/api/src/server.ts`, before the database connection: it checks every variable name against `FORBIDDEN_ENV_PATTERNS` and in production throws `EnvPolicyError`, which `start()` logs before exiting 1; elsewhere it warns. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- The name check is a denylist and is apps/api's alone: a variable that matches no pattern passes whether or not `CLAUDE.md` permits it, and apps/web runs no name check because it legitimately carries `NEXTAUTH_*`. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata), [ADR-046](../046-web-server-refuses-tls-verification-switched-off.md)
- Beside the names, `assertEnvPolicy` refuses `NODE_TLS_REJECT_UNAUTHORIZED` only when its value is exactly `0`, by a refused start in production and a warning elsewhere; any other value, the empty string included, passes without a warning. [ADR-045](../045-bootstrap-guard-refuses-tls-verification-switched-off.md)
- That value check and its message exist once, as `tlsVerificationOffProblem` in the main entry of `@luke/core` (`packages/core/src/runtime/tlsVerification.ts`), called by apps/api's `assertEnvPolicy` and apps/web's `register()`. [ADR-045](../045-bootstrap-guard-refuses-tls-verification-switched-off.md#errata), [ADR-046](../046-web-server-refuses-tls-verification-switched-off.md)
- apps/web refuses the value in `register()` (`apps/web/src/instrumentation.ts`), in the Node.js runtime only: in production (`isProduction()`, fixed when the image is built) it writes `[env-policy] …` to the console and calls `process.exit(1)`, elsewhere it warns through `debugWarn`. [ADR-046](../046-web-server-refuses-tls-verification-switched-off.md)
- The web start window is accepted: between `listen` and the exit Next may answer static files and the HTTP rewrites to apps/api, and the choice is revisited when a rewrite targets an `https` destination or a `middleware.ts` or `proxy.ts` makes outbound calls. [ADR-046](../046-web-server-refuses-tls-verification-switched-off.md)
- The TLS check covers the two server starts only: `prisma migrate deploy` in `entrypoint.sh`, the `db:*` scripts and the seeds do not pass through it. [ADR-045](../045-bootstrap-guard-refuses-tls-verification-switched-off.md)
- `luke-no-direct-env` (`.semgrep/rules/no-direct-env.yml`) rejects every use of `process.env` in application code except a dot read of a `NEXT_PUBLIC_*`, `NODE_ENV` or `APP_VERSION` name; one read is exempted in place with a reasoned `// nosemgrep: luke-no-direct-env`, and whole-file exclusions remain for the test and script trees and a few modules. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- `apps/web/src/auth.ts` throws when `NEXTAUTH_SECRET` is absent in production; outside production it derives the secret from the master key. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md)
- Every AppConfig key is declared in `AppConfigRegistry` (`packages/core/src/schemas/config.ts`) with a Zod schema, numeric bounds included, every value is stored as a string, and `saveConfig` and `saveConfigs` accept only a registered key and validate its plaintext against that schema before writing. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md)
- A setting that is not configured is absent, removed with `deleteConfig`, never stored empty; `integrations.auth.saveLdapConfig` removes an empty mapped value and keeps the stored Bind DN or bind password when either is left blank. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- Defaults are declared once, in `APP_CONFIG_DEFAULTS`: `getConfigOrDefault` falls back with a warning on a stored value the registry refuses, while `getStoredConfigOrDefault` throws `InvalidStoredConfigError`, naming the key and never the value, where the fallback would silently do the wrong thing (`storage.type`, `backup.schedule.scope`). [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- Application code reads configuration through `getConfig`, `getTypedConfig`, `getConfigOrDefault` and `getStoredConfigOrDefault` in `apps/api/src/lib/configManager.ts`, never from `process.env`; all four decrypt a row flagged `isEncrypted`, with no option not to, and a value that does not decrypt throws instead of falling back to the default. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- `getConfigForForm` and `getLdapConfigForForm` return a row that does not decrypt as a blank value with a flag instead of throwing, so a settings form opens for an admin to repair it; besides the forms, `integrations.google.testConnection` reads the refresh token through `getConfigForForm` and answers an unreadable one without connecting. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- Readers still bypass `configManager.ts`'s decrypting readers with Prisma, among them: `isLdapEnabled` reads `auth.ldap.enabled` as stored through its registry schema, a refused value (ciphertext included) counting as off, and `getRbacConfig` (`packages/core/src/server/rbacConfig.ts`) reads `rbac.sectionAccessDefaults` and `app.sections.disabled`. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- An encrypted value is AES-256-GCM under the 32-byte master key in `~/.luke/secret.key`, written by `encryptValue` in `configManager.ts` as `iv:authTag:ciphertext`, and `AppConfig.isEncrypted` records per row whether it is encrypted. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md)
- Every writer — `prepareConfigWrite` behind `saveConfig` and `saveConfigs`, and the seed — stores a key of `SECRET_CONFIG_KEYS` encrypted and a key of `PLAINTEXT_CONFIG_KEYS` in plaintext whatever the caller asks, the audit rows, responses and import preview report the stored state, and `db:encrypt-secret-config` encrypts a credential row an earlier release stored in plaintext. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- For every other key an explicit `encrypt` flag decides, and an omitted one in `saveConfig`, `config.set`, `config.update` and `config.setMultiple` keeps a stored key's choice and stores a new key in plaintext, decided by `saveConfigs` under the AppConfig write lock that `deleteConfig` and `saveSectionsDisabled` also take; `config.importJson` still reads an absent flag as plaintext. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- `auth.strategy` and `auth.ldap.enabled` are written only by `saveAuthConfig` (`apps/api/src/services/authConfig.service.ts`), reached through `integrations.auth.saveStrategy` and `integrations.auth.saveLdapConfig`, in one transaction that takes the last-admin lock and then the AppConfig write lock and refuses `ldap-only` without LDAP on or without a break-glass administrator; `config.set`, `config.update`, `config.setMultiple` and `config.importJson` (per item) refuse every key with a dedicated writer except `app.sections.disabled`, and `auth.ldap.enabled` cannot be deleted. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- Three writes bypass `saveAuthConfig`: the seed's `auth.strategy`; a full restore, whose `pg_restore --clean` leaves both keys as the backup holds them, unchecked; and `scripts/refresh-rc-db.sh`, which deletes `auth.ldap.enabled` with SQL. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- Every AppConfig mutation records an audit row when it succeeds — the `config.*` writers, the integration, storage and maintenance settings procedures, `phaseAlert.updateThresholds` and `sectionAccess.setRoleDefaults` — except the maintenance scheduler's state writes (`markActivated`, `recordWarningsSent`), an open gap, and the seeds and scripts under `apps/api/prisma` and `apps/api/scripts`, which run outside the API. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md#errata)
- `CRITICAL_CONFIG_KEYS` names the keys apps/api cannot start without: the API exits when it cannot reach the database and, in production only, when a critical key is missing or invalid; elsewhere it warns. [ADR-018](../018-runtime-configuration-and-bootstrap-environment.md)
- Reading a decrypted value through the config router requires `config:update`; `config:read` returns stored and masked values only. [ADR-034](../034-outbound-boundary-for-sensitive-data-and-masked-configuration-reads.md) (Secrets and sensitive data)
